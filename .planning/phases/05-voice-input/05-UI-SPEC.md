# Phase 5 — UI Design Contract

> Visual and interaction contract for voice input: the CarPlay push-to-talk mic button, the phone permission onboarding screen, and the (UI-free) Siri App Shortcut. Generated by gsd-ui-researcher, pending verification by gsd-ui-checker.
>
> **Surfaces:** (1) CarPlay mic button — native UIKit floating subview of `CarPlayViewController.view` over the webview; (2) phone permission onboarding — native SwiftUI Form in the phone shell (HowTo screen style); (3) Siri — zero custom UI; only App Shortcut metadata. All CarPlay values in **points (pt)**; CarPlay is always-dark with no light variant. System fonts, system colors, SF Symbols only — inherits the Phase 4 contract (04-UI-SPEC.md) as the visual baseline.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native UIKit + SwiftUI; shadcn not applicable — not a web target) |
| Preset | not applicable |
| Component library | UIKit: `UIButton` (type `.custom`), `UILabel`, `CABasicAnimation`; SwiftUI: `Form`, `Section`, `Text`, `Button` (system components, phone surface only) |
| Icon library | SF Symbols (`mic.fill`, `magnifyingglass`) — existing app convention |
| Font | SF Pro via `UIFont.systemFont` / SwiftUI system text styles — no custom fonts |

**Precedent:** CarPlay surface extends the Phase 4 contract (black `#000000` dominant, `#1C1C1E` secondary, `#FF3B30` accent, white text, 4pt spacing scale). Phone surface follows the existing `HowTo` Form style and ContentView typography (20pt title, 12pt footnote). The mic button is a floating subview of `CarPlayViewController.view` — NOT inside the results overlay (Phase 4 z-order reservation note).

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon optical adjustment, pill inner icon-to-text gap |
| sm | 8pt | Vertical pill padding, gap between mic button and listening pill |
| md | 16pt | Mic button inset from top safe-area and trailing screen edge; horizontal pill padding |
| lg | 24pt | Onboarding section spacing (Form default), reserved |
| xl | 32pt | Not used this phase (reserved) |

**Exceptions (driver-glance rules — locked by VOX-01):**
- Mic button diameter: **56pt** (≥44pt hit-target rule exceeded deliberately for driving; 56pt is a 4pt multiple so no scale exception is introduced).
- All tappable targets: **≥44×44pt** (rule; the mic button and phone buttons use system heights ≥44pt).
- Mic button corner radius: **28pt** (= diameter/2, circular).

## Color

CarPlay surface (explicit hex — we own the drawing):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` pure black | Listening/hint pill backgrounds (matches `KeyboardView`/overlay black) |
| Secondary (30%) | `#1C1C1E` | Mic button idle fill |
| Accent (10%) | `#FF3B30` (systemRed) | Mic button **listening-state fill only** |
| Text primary | `#FFFFFF` | "Listening…" label, hint pill text, mic icon |
| Destructive | none | No destructive actions this phase |

Phone surface (system semantic colors, SwiftUI convention): `systemBackground`/`systemGroupedBackground` surfaces, `.primary`/`.secondary` text, with one explicit accent use below.

**Accent reserved for:** (1) mic button listening-state fill (`#FF3B30` replaces `#1C1C1E` while recording), (2) phone onboarding CTA "Enable Voice Search" (`#FF3B30` — single accent identity across both surfaces; NOT system blue). Never used for the idle mic button, borders, decoration, or any phone element other than the CTA. Contrast: white icon/label on `#FF3B30` ≈ 3.9:1 at 17pt+ semibold passes WCAG AA large-text; on `#1C1C1E` ≈ 15:1. *(Defaults — see open questions Q1, Q7 in phase report.)* Focal points: idle screen — the 56pt mic button (the only accent-free floating element, top-right); listening — the red pulsing button is the single brightest element on screen (2.5.14 recording indication).

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Touch-down on mic button | Start listening: fill flips `#1C1C1E` → `#FF3B30`, pulse animation begins (scale 1.0↔1.1, 0.8s, autoreverse, repeat), "Listening…" pill appears. Audio session held only while listening. |
| Touch-up (`.touchUpInside`, `.touchUpOutside`, `.touchCancel` — all identical) | Stop listening, submit final transcript → `SearchCoordinator.search(transcript)` → Phase 4 overlay appears with its "Searching…" loading row. Button returns to idle fill; pill hides. |
| Auto-stop on silence (VOX-01) | Buffer-based recognition has NO system end-of-speech detection (SDK-verified; see 05-RESEARCH.md Pitfall 2) — auto-stop is app-side: a silence timer on partial-transcript timestamps (~1.8s without transcript change finalizes and submits, 10s hard cap) plus touch-up submit. Finalization submits exactly as touch-up would. One press = one recognition session; no re-arm while held. *(Corrected from Q3's default by research.)* |
| Empty transcript on session end | Hint pill "Didn't catch that" (1.5s); results overlay NOT shown; no API call spent. |
| Recognition failure mid-session / unavailable | Hint pill "Voice search unavailable" (1.5s); button visibility re-evaluated (hidden if on-device support is gone). Never falls back to server-based recognition (ARCHITECTURE.md Anti-Pattern 5). |
| Overlay visibility vs mic button | While the Phase 4 results overlay is visible, the mic button is **hidden** (`isHidden = true`): prevents spatial conflict with the header attribution row, blocks a second in-flight voice search (quota discipline, SRCH-02), and avoids double-submits. Button reappears on overlay dismissal if still authorized. *(Default — Q2.)* |
| Denied / not-determined / unsupported | Button never appears — visibility gate requires speech `.authorized` AND mic granted AND `supportsOnDeviceRecognition == true`. No prompt is ever triggered from the CarPlay scene (Pitfall 9). Typed keyboard and Siri paths remain fully usable — no dead ends (VOX-01/roadmap SC-4). |
| Phone CTA "Enable Voice Search" | Requests speech authorization, then mic permission on completion (both purpose strings committed with this code — VOX-02). System prompts render on the phone; the screen's state section updates from the results. |
| Phone denied state | "Open Settings" deep-links to the app's Settings pane; status re-read on `scenePhase == .active`. |
| First-run presentation | On ContentView appear, if speech status `.notDetermined` → present VoiceSearchSetup sheet once; never auto-present again once determined (either outcome). Persistent "Voice Search" row provides later access. *(Default — Q4.)* |
| Siri phrase (VOX-03) | "Hey Siri, search YouTube for X" → `SearchCarTubeIntent.perform()` in-process → `SearchCoordinator.search(query)` → Phase 4 overlay states on the CarPlay screen. Zero custom Siri UI; the App Shortcut metadata row above is the entire Siri visual surface. |

**Z-order (extends the Phase 4 stack in `viewDidLoad()`):**

```
webView → noSleepView (hidden) → keyboardView (hidden)
        → resultsController.view (hidden; Phase 4)
        → micButton (hidden unless authorized; insertSubview belowSubview: screenOffLabel)
        → screenOffLabel → splash (temporary)
```

Mic button inserts above the webview, below `screenOffLabel`, exactly as the Phase 4 reservation note specifies. Mic button and results overlay are never visible simultaneously, so their relative z-order is moot.

**Hard constraints:** no permission request, alert, or prompt ever originates from the CarPlay scene (Pitfall 9 — prompts render only on the phone); listening state must be visible at a glance without audio cues alone (2.5.14); no scroll is introduced on the CarPlay surface (phone Form scrolls normally); the webview is never resized, navigated, or blocked while listening (Phase 4 UI-01 hard constraint extends to the mic surface).

## UI Considerations

> Populated by the ui-phase UI-consideration probe and lifted by plan-phase's `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state* coverage. Empty/error COPY lives in `## Copywriting Contract` above.

Applicable state considerations resolved: 10 covered (verification: explicit), 5 dismissed with reason, 0 backstop, 0 unresolved

| Category | Element | Status | Resolution / Reason |
|----------|---------|--------|---------------------|
| loading | mic button | ✅ covered | Listening state: accent fill + 0.8s pulse + "Listening…" pill from touch-down until session end (explicit, Interaction Contract) |
| error | mic button | ✅ covered | Empty transcript → "Didn't catch that" hint; recognition failure → "Voice search unavailable" hint + visibility re-check; overlay never shown on failure (Copywriting Contract) |
| error | mic button availability | ✅ covered | On-device recognition unsupported/withdrawn → button hidden, identical to denied; keyboard and Siri paths unaffected (Interaction Contract) |
| empty | phone onboarding | ✅ covered | Not-determined initial state renders explainer + CTA ("Voice Search" heading, Copywriting Contract); no data to be empty beyond this |
| loading | phone onboarding | ✅ covered | System permission prompts are modal system UI owned by iOS; screen state updates on completion — no custom loading UI |
| error | phone onboarding | ✅ covered | Denied (either or both permissions) renders "Voice search is off" + Open Settings deep-link; partial grant treated as denied (both required for the button) |
| partial | phone onboarding | ✅ covered | One permission granted + one denied → denied state copy; no half-enabled visual state exists |
| long-text | phone onboarding explainer | ✅ covered | 17pt regular wraps freely inside Form sections; no truncation on any phone width |
| loading | transcript→results handoff | ✅ covered | Touch-up/finalization immediately shows the Phase 4 overlay's "Searching…" loading row — voice path reuses the existing loading state verbatim (inherited by reference) |
| populated | voice query results | ✅ covered | ≤8 rows render per the Phase 4 populated contract; identical layout and copy for typed and spoken queries (zero-one-many: no count-dependent copy, inherited) |
| empty / error / populated | results overlay states | dismissed | Owned entirely by the Phase 4 contract (04-UI-SPEC.md UI Considerations table); Phase 5 submits queries into it and re-declares nothing |
| overflow / long-text | listening pill, hint pills | dismissed | Fixed single-line short static strings ("Listening…", "Didn't catch that", "Voice search unavailable"); cannot exceed the pill at any head-unit width — same rationale as Phase 4's header attribution |
| overflow | mic button | dismissed | Fixed 56pt circular control; icon-only; no content to overflow |
| zero-one-many | mic button | ✅ covered | Exactly one button exists or none (visibility gate); no collection semantics apply — single control, single state machine (idle/listening/hint) |
| partial | listening session | dismissed | Speech is fire-and-forget into a final transcript string (ARCHITECTURE.md); no partial-transcript UI exists by design — Live partial transcripts are NOT shown |
