# Phase 4 — UI Design Contract

> Visual and interaction contract for the CarPlay search results overlay. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Surface type:** Native UIKit on the CarPlay scene window (`UIWindowSceneSessionRoleCarPlay`). Not SwiftUI, not web. All values in **points (pt)**. CarPlay screens are an always-dark context — no light variant exists. System fonts and system colors only; no custom font or color-asset dependencies.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native UIKit; shadcn not applicable — not a web target) |
| Preset | not applicable |
| Component library | UIKit: `UITableViewController` + custom `UITableViewCell`, `UIActivityIndicatorView`, `UIButton` (type `.system`), `UILabel` |
| Icon library | SF Symbols (`UIImage(systemName:)` — existing app convention, e.g. `delete.left`, `arrow.left`) |
| Font | SF Pro via `UIFont.systemFont` / `monospacedDigitSystemFont` — no custom fonts |

**Precedent:** the overlay extends the existing `KeyboardView` wiring pattern (child VC of `CarPlayViewController`, added in `viewDidLoad()`, toggled via `isHidden`). Visual language inherits the keyboard's black/white/gray monochrome base.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Thumbnail-to-text gap, badge inner padding |
| sm | 8pt | Thumbnail corner radius, intra-row label gaps, header vertical padding |
| md | 16pt | Row content insets (leading/trailing), thumbnail-to-vertical-edges inset |
| lg | 24pt | Header block bottom padding, empty/error row content padding |
| xl | 32pt | Not used this phase (reserved) |

**Exceptions (driver-glance rules — locked by UI-01):**
- Row height: **≥60pt minimum** (use 68pt default via `UITableView.automaticDimension` with a 60pt floor).
- Close button hit target: **≥44×44pt**.
- Full-screen overlay frame: `view.bounds`, autoresized via `autoresizingMask = [.flexibleWidth, .flexibleHeight]` — never a fixed 720pt width.
- Thumbnail: **106×60pt** (16:9 at 60pt height), corner radius 8pt.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Row title | 22pt | semibold (600) | 26pt (≈1.18), max 2 lines, tail truncation |
| Row channel | 17pt | regular (400) | 20pt (≈1.18), 1 line, tail truncation |
| Close button title | 17pt | semibold (600) | single line, default button height within ≥44×44pt target |
| Row duration | 15pt | regular (400), monospaced digits | 18pt (1.2), 1 line |
| Header / attribution | 13pt | regular (400) | 16pt (≈1.23), 1 line |

Exactly 2 weights (regular + semibold), 4 sizes (22/17/15/13). Title at 22pt semibold is readable at arm's-length glance distance on 480–800pt-wide head units; nothing smaller than 13pt appears on this surface.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` pure black | Overlay background (matches `KeyboardView` black) |
| Secondary (30%) | `#1C1C1E` | Thumbnail placeholder fill, row selected/highlighted background |
| Separator | `#333333` | Row separators (inherits keyboard border: `UIColor(hue:0, saturation:0, brightness:0.2)`) |
| Text primary | `#FFFFFF` | Row titles, channel, Close button title |
| Text secondary | `#8E8E93` (systemGray) | Attribution text, empty/error body copy |
| Accent (10%) | `#FF3B30` (systemRed) | Spinner tint (loading + fallback states), "Try another search" action text in empty state |
| Destructive | none | No destructive actions this phase |

Accent reserved for: **(1)** `UIActivityIndicatorView` tint in the loading row and the fallback transition row, **(2)** the "Try another search" action label in the no-results row. Never used for row selection, Close, borders, or decoration. Text-primary/text-secondary pairs meet ≥7:1 contrast (white on black = 21:1; systemGray on black ≈ 7.4:1) — high-contrast for daylight/brightness variation in cars. The accent pair (#FF3B30 on #000000 ≈ 5.9:1) is used only for the spinner and a 17pt+ action label, where it passes WCAG AA large-text 3:1. *(Default — see open question Q1 in phase report.)* Focal point: the first result row (106×60 thumbnail + 22pt semibold title) anchors the populated screen; the red spinner anchors loading and fallback states.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Result row tap — plays immediately, no confirmation. (Explicit label CTA in empty state below.) |
| Attribution (locked, UI-03) | "Results from YouTube" — header, secondary color, visible in ALL states (header persists in empty, loading, and fallback states) |
| Close affordance | "Close" — header top-left button |
| Loading state | "Searching…" (single row: spinner + label, centered) |
| Empty state heading | "No results" |
| Empty state body / next step | "Nothing matched that search." + action "Try another search" → dismisses overlay and shows keyboard |
| Error state (quota/key 403) | "Search unavailable" + "Showing YouTube web search instead." — then auto-dismiss (see interaction contract) |
| Destructive confirmation | none — Close is non-destructive (playback continues beneath), fires with no confirmation |

## Component Inventory

| # | Component | Implementation |
|---|-----------|----------------|
| 1 | `SearchResultsViewController` | `UITableViewController`, plain style, opaque black, full-screen child VC of `CarPlayViewController` (Pattern 1, ARCHITECTURE.md) |
| 2 | Result cell | Custom `UITableViewCell`: 106×60 thumbnail (async `URLSession` load, `#1C1C1E` placeholder, radius 8) + title (2-line) + channel (1-line) + duration badge (bottom-right of text block or trailing, monospaced digits, e.g. "12:34" / "1:02:03") |
| 3 | Header view | Table header: "Close" button (top-left, ≥44×44pt, white title 17pt semibold) + "Results from YouTube" attribution (13pt, `#8E8E93`) |
| 4 | Loading row | Spinner (`#FF3B30` medium style) + "Searching…" — shown while `isSearching == true` |
| 5 | No-results row | "No results" / "Nothing matched that search." + "Try another search" action |
| 6 | Fallback row | "Search unavailable" / "Showing YouTube web search instead." + spinner — shown on quota/key failure while the webview fallback loads |

**Row count contract:** API requests `maxResults=10` (Phase 3); display **`min(results.count, 8)`** rows — first 8, no pagination, no infinite scroll. 8×68pt fits a 720pt-tall head unit with header; shorter screens scroll within those ≤8 rows only (acceptable — bounded, not scroll-heavy).

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Tap result row | Highlight (`#1C1C1E` fill) → `CarPlaySingleton.shared.loadUrl(YT_EMBED + videoId)` (existing playback path) → dismiss overlay. Single tap, no confirmation, no detail screen. |
| Tap "Close" | Dismiss overlay. Webview untouched — playback continues exactly as-is. |
| Tap "Try another search" (empty state) | Dismiss overlay → `toggleKeyboard()` (existing) so the driver can retype. |
| Dismissal mechanics | `resultsController.view.isHidden = true` — no animation, identical to keyboard toggling. Restoration is zero-layout: webview was never resized. |
| **Hard constraint (UI-01)** | Overlay MUST NOT resize, reload, or navigate the webview beneath. The keyboard precedent *shrinks* the webview — search results deliberately must not. Webview frame remains `view.bounds` for the entire overlay lifecycle. |
| Fallback (SRCH-03) | On 403/quota/key failure: show fallback row (6), trigger webview fallback (`searchVideo(query)` existing path), auto-dismiss the overlay after 2.0s or when fallback navigation commits — whichever first. Never a dead screen. |
| Loading entry | Overlay appears with loading row the moment a query is submitted (before network completes) so the driver gets immediate feedback. |

**Z-order (extend existing stack in `viewDidLoad()`):**

```
webView → noSleepView (hidden) → keyboardView (hidden)
        → resultsController.view (hidden; insertSubview belowSubview: screenOffLabel)
        → screenOffLabel → splash (temporary)
```

**Phase 5 reservation (do NOT implement now):** the mic button will pin top-right of `CarPlayViewController.view`, above the webview, below `screenOffLabel` — a floating subview, NOT inside the results overlay. The results header needs no reserved space for it; the two surfaces never overlap in z-management responsibility.
