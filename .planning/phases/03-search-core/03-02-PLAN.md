<objective>
Deliver the YouTube Data API v3 client as a stateless, Foundation-only leaf: typed errors, key injected at init (bundle read only in the default initializer), decode of search.list + videos.list into flat SearchResult values, proven by fixture-JSON unit tests that never touch the network.

Implements SRCH-01 (the parsed-results half: key consumption + two-request shape) and the search-client half of SRCH-04. The quota budget surface (one page, no pagination) and the degrade decision function are encoded here where they belong in the API design; their behavioral tests land in plan 03-03 (SRCH-02, SRCH-03).

Purpose: This is the project's first network client with typed errors and first Codable decode; the pattern-map deviations 1-8 (error typing, Codable-not-JSONSerialization, injected URLSession, Constants-file URLs, Foundation-only, budget-in-surface, async/await, two-request duration) are all new convention set here.
Output: Search/ group with model + service, four fixtures, service tests with URLProtocol stub, pbxproj wiring.
</objective>
